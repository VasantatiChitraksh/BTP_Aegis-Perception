BASELINE SUITE v1 — 20 October 2026

Order: attention Pix2Pix -> Restormer, one A100 at a time. Vanilla Pix2Pix removed.
Attention Pix2Pix starts with random weights. Restormer starts from the SAME
official deraining.pth weights as the successful original 60-epoch run, verified
by SHA-256. It is not trained from scratch. This repeats that initialization and
60-epoch optimization recipe on the frozen v3 pool; it does not resume the
original project's best.pt or the rejected 20-epoch fine-tunes.
The goal is to match or improve the previous model; improvement is not guaranteed.
The previous checkpoint is retained. One seed is not a significance claim.

No images downloaded, synthesized, copied, or moved between train/val/test.
Reserve images stay out: they belong to held-out scenes/sequences, not spare training.
Known groups and decoded targets are checked for leakage. This cannot certify all
unknown capture sequences. Smoke has only 31/6/6 background groups in train/val/test.
The protocol JSON's historical fine-tuning notes apply to old runs; this suite
reuses its split/strata and hashes, not its old optimization/initialization policy.

TRAINING
60 sampled epochs/model, 4096 draws/epoch, batch 4 = 61,440 optimizer steps/model.
Each draw: weather probability rain/fog/snow/smoke = .30/.30/.30/.10, then
uniform background, then uniform variant, WITH replacement. Repeated images
are expected; 4096 is not a full pass through the training pool. This retains
the original successful run's probabilities, not the later quarter-per-weather
stratified-cycle fine-tune. It does not prove that the sampler caused that failure.
Sampling and crop/flip RNGs are independent of model/dropout RNG, so all models
see the same image IDs and augmentations. Seed 42; paired 256x256 crops;
native-resolution validation/test, automatic pad/crop without resizing or tiling.

Attention Pix2Pix: existing six-level 64-channel U-Net with gated skip connections.
Existing five-convolution PatchGAN
has a 94x94 receptive field (four stride-2 layers plus final stride-1 layer).
This is a repository Pix2Pix-style baseline, not an exact reproduction of the
official eight-level U-Net/70x70 PatchGAN. Adversarial BCE + 100*L1 on [-1,1].
Adam lr 1e-4, betas .5/.999, no weight decay, cosine decay to 1e-6, BF16.
Restormer: full dim48 [4,6,6,8] topology; RGB-equivalent L1; AdamW lr 1e-4,
betas .9/.999, decay 1e-4, cosine to 1e-6, BF16. Both use gradient clip 1.
Matched data/update budget is not a guarantee that every architecture converges
equally in 60 epochs. Report learning curves and GPU-hours with the comparison.
GAN objectives may improve appearance while losing PSNR; no gains are promised.
Objective reference: https://github.com/junyanz/pytorch-CycleGAN-and-pix2pix

SELECTION / TEST
Save best validation equal-weather/background/stratum PSNR; record SSIM for every
weather. Selecting each run's best epoch is not claiming it beats the original.
Only after epoch 60, evaluate that fixed checkpoint on all 2334 test pairs.
Each weather contributes 25% to headline PSNR/SSIM, regardless of image count.
Always include four per-weather rows and raw-input comparisons; image-weighted
all-image mean is secondary. Save per-image metrics and cluster-bootstrap intervals.
No test-driven retuning: both configs are frozen before submission.
This is a previously inspected benchmark, not a new untouched external test set.
After Restormer's test, comparison_previous.json compares it with the successful
original model's saved predictions on exactly the same 2334 test IDs. It reports
paired cluster-bootstrap intervals and every PSNR/SSIM regression, including
per-weather regressions hidden by a higher overall score. This is a final
benchmark report, not test-based epoch selection or automatic model replacement.

UNATTENDED EXECUTION
Submit once: bash scripts/restoration/submit_baseline_suite.sh
Before queuing, official weights are checked and reused from
/scratch/$USER/aegis-four-weather/artifacts/pretrained/deraining.pth via symlink.
AEGIS_PRETRAINED_DIR can override that directory. Missing or wrong weights stop
submission; there is no random-initialization fallback or duplicated weight file.
Six dependent stages: epochs 1-20, 21-40, 41-60 for each model. Full 60-epoch
scheduler and optimizer state resume unchanged at the boundaries. Stage limit
20 hours, one GPU, eight CPU slots, 32000 MiB host RAM. GPU audit/preflight checks
all data and the largest validation/test input shapes before the first training.
Only best.pt and last.pt retained per model, no redundant epoch checkpoints.
SSH disconnect does not stop submitted jobs. Training/test failures halt the chain;
invalid dependencies cancel downstream jobs. No automatic infinite retries.
After resolving a failure, and only when old jobs have ended:
  bash scripts/restoration/submit_baseline_suite.sh --resume
This resumes from the last complete epoch and skips completed work. Partially
completed epochs are replayed. Do not change configs/source during the chain.
SLURM reference: https://slurm.schedmd.com/sbatch.html
