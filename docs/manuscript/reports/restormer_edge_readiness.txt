 The deployment geometry is a deliberate tradeoff
 Each image is resized with its aspect ratio preserved, padded to 256×448, restored, and returned to its
 original dimensions before detection. This reduces compute but may remove small-object details. The original
 32.58 dB / 0.9297 native-resolution restoration score is not the score of this resized pipeline.

 Local validation passed; edge acceptance has not happened
 The laptop is CPU-only. No TensorRT engine, Jetson FPS, thermal limit, power draw or device memory result
 has been measured. Engines must be built and tested on the actual Jetson. The package does not contain
 invented hardware results.

 Local CPU smoke timing: five ONNX model calls after two warmups, median 14.94 seconds. This short measurement checks
 execution only; it is not an edge-performance forecast.

 Across the pilot, restored minus original mAP50–95 is +2.89 percentage points; restored minus resize-only
 is +3.60 points. These are observed pilot differences, not a statistical superiority claim.

 Bold marks the highest value within each weather group. Values are percentages. Precision/recall use the maximum-F1
 confidence; mAP uses conf=.001, IoU=.7 NMS and up to 300 detections. Overall AP is pooled across the 72 images, not the
 arithmetic mean of weather AP.

 03 / QUALITY CONTROLS & HANDOFF


 A testable next step.
 Data checks that make the comparison interpretable
 All 704 available DAWN annotation pairs were checked: 300 fog, 200 rain and 204 snow images; 5,610 boxes
 across six road classes. Source TXT IDs were corrected to COCO IDs only in derived evaluation labels; every
 box was checked against VOC XML. One train object is outside the six-class scope. 17 exact duplicate groups
 were found; image counts must not be treated as independent scene counts.

 No DAWN smoke detection labels are available in this project. COCO pretraining overlap is unverified. Pilot
 image choices, source hashes, class-level results and the full annotation audit are saved in JSON. The full
 704-image evaluation is supplied as a separate resumable command; it was not run for this handoff.

 Device acceptance sequence

  STEP                             PASS CONDITION


  1 · Verify & preflight           Package checksums match. CUDA/TensorRT/OpenCV imports work. Actual hardware,
                                   free memory and software versions are recorded.


  2 · Compile locally              Build one engine at a time. FP16 uses FP32-sensitive transformer math. No changes to
                                   system power modes or drivers.


  3 · Precision gate               Finite output; restoration numerical agreement plus per-fixture PSNR drop ≤0.1 dB and
                                   SSIM drop ≤0.001. Reject failed candidates and retain FP32 fallback.


  4 · Sustained run                Measure original, resize-only and restored paths with identical settings; record
                                   median/p95, wall throughput and tegrastats.


  5 · Adoption decision            Check longer videos and untouched labelled data. Keep raw detection available. Small
                                   fixture tests alone do not establish field reliability.
