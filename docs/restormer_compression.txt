RESTORMER COMPRESSION: EXPERIMENTS AND DEPLOYMENT DECISION
======================================================

Status: Restormer FP32 ONNX is validated. No Jetson FP16 or INT8 engine has
been measured. Original checkpoints and Chitraksh's files remain unchanged.
The local pruning results are a four-image rejection screen, not a new test
benchmark. See artifacts/edge_v1/reports/restormer_compression_screen.json.

These means are over FOUR validation images, not the 2,334-image test set.
2:4 removes 39.68% of all convolution weights because ineligible layers remain
dense. All variants have exactly 104,696,534 serialized dense state-dict bytes
and unchanged parameter counts. No GPU speed or memory benefit was measured.
The gate requires each image to pass: at 10%, fog loses 1.67 dB and snow loses
2.82 dB despite small PSNR increases on rain and smoke. No candidate is promoted.
The initial screen was resumed after correcting a 2:4 storage-aliasing error;
the correction is covered by tests, and the completed earlier variants were
preserved. Raw local provenance retains both script hashes.

Verification: 19 deployment/compression tests pass, including 2:4 channel-axis
correctness and orchestration failure handling. CPU raw-detector smoke execution
also passed. TensorRT hardware paths remain unexecuted on this CPU workstation.

What the earlier contribution supplies
--------------------------------------
quantization/scripts/prune_model.py provides global/local magnitude pruning.
The new screen imports its global pruning and mask-removal functions directly.
It evaluates correctly mapped RGB [-1,1] outputs against clean validation
targets, rather than using the original model's output as the PSNR target.
It also reports parameter-weighted sparsity; averaging layer percentages can
misrepresent the fraction of weights removed.

quantization/scripts/quantize_compare.py targets nn.Linear for dynamic INT8.
This Restormer has 274 Conv2d modules and zero nn.Linear modules. The executed
conversion therefore produces zero quantized Linear modules; unchanged tensor
values are recorded. Do not present this no-op as an INT8 Restormer result.
Its static CPU route and single-image calibration are not a Jetson experiment.

quantization/scripts/export_tensorrt.py contains a calibration placeholder.
The separate edge_build.py implements actual training-only calibration and
numeric acceptance gates for the supported TensorRT versions. This is code
prepared for device execution, not a completed hardware quantization result.

Why pruning is an experiment rather than an automatic improvement
----------------------------------------------------------------
Global unstructured pruning zeroes weights but keeps tensor dimensions and
dense parameter storage. It does not alone reduce dense GPU operations or
ordinary uncompressed state-dict size. A ZIP compression improvement would
not establish an inference-memory reduction or a speedup.

The additional 2:4 screen removes the two smallest magnitudes out of each four
input channels, independently at each output channel and spatial kernel
position. Grouped/depthwise convolutions and channel counts not divisible by
four remain dense. This prepares a sparsity pattern only. Hardware benefit
requires eligible TensorRT sparse tactics actually being selected and timed.
No speedup is claimed and no pruned graph is promoted by this local screen.

Channel pruning would change Restormer's shapes and needs careful dependency
handling across residual connections, attention heads and pixel shuffle.
Both structured pruning and quantization-aware training can require recovery
training. That is outside the current no-retraining/no-architecture-change
scope. Failed one-shot pruning does not prove recovery training cannot work.

Local reproduction
------------------
From the maintainer's repository with the existing model/data artifacts:
  .venv/bin/python scripts/deployment/edge_compression_screen.py

Use --output NEW_DIRECTORY for a fresh run; --resume resumes an interrupted
screen after verifying its checkpoint, fixture and pruning-source hashes.
Methods: original FP32, legacy global 10%, 30%, 50%, and channel-wise 2:4.
Exactly the same four validation images and 256x448 geometry are used.
Per-image gates are PSNR drop <=0.1 dB and SSIM drop <=0.001. These engineering
thresholds are fixed before scoring, not statistical significance tests.
Passing permits a larger validation study; it does not qualify deployment.
Neither test data nor final test scores are used to tune compression.

Jetson comparison: the next required experiment
-----------------------------------------------
Use the new package aegis_restormer_edge_compression_20261024.tar.gz and its
.sha256 file. Extract it into a fresh directory. Follow SETUP.md for the
JetPack environment, then from the extracted directory run:

  export AEGIS_PYTHON="$PWD/.venv/bin/python"
  bash scripts/deployment/edge_compression_device.sh

This builds one fixed YOLOv8n FP16 detector, then Restormer FP32, mixed FP16,
and calibrated mixed INT8 sequentially. It compares the same samples with
the same detector and preprocessing. It does not overwrite the normal
engines/restormer_fp16.engine file. Compilation/validation failures are logged,
skipped for inference, and reflected in status.tsv and the nonzero exit code.
Existing model-specific precision failures do not prevent later comparisons.

Collect:
  results/*_compression/status.tsv
  results/*_compression/device_comparison.csv and .json
  results/*_compression/build_*.log and run_*.log
  results/*_compression/tegrastats_*.log (if tegrastats is installed)
  engines/comparison_*.json (validation and actual engine sizes)
  engines/comparison_*.layers.json (actual layer formats and tactics)

The INT8 builder flag alone does not establish INT8 layer coverage. Inspect
the layer information; sensitive transformer math remains FP32, and the
builder may use FP16 elsewhere. The 64 calibration inputs are training-only,
16 per weather, with background rotation. They are an initial PTQ trial, not
evidence of adequate calibration. If accuracy fails, compare more training
backgrounds/severities and calibration methods using validation, not test.
Hold back a larger validation panel for confirmation after choosing settings.

This kit uses the calibrated implicit-INT8 interface available in TensorRT
8.5/8.6 and 10.x. NVIDIA recommends explicit Q/DQ for newer workflows and has
removed the old calibration interface in TensorRT 11; this kit rejects 11.
Do not upgrade JetPack blindly. Once the installed JetPack/TensorRT is known,
explicit Q/DQ is the appropriate migration path if needed, with new numerical
and hardware validation. No Q/DQ export or QAT is claimed here.

Final comparison required for the professor
------------------------------------------
For each successful candidate record: engine bytes, actual layer precisions,
PSNR and SSIM per weather, detector mAP/recall, median/p95 latency, throughput,
peak system RAM, and measured power/temperature under the same power mode.
Keep resolution, inputs, detector, warmup, cooling and measurement scope fixed.
Repeat timing experiments to assess variability; one run is only preliminary.
Power channels in tegrastats are device-specific: identify the rail before
reporting watts or energy/frame, and do not report total system RAM as model RAM.

Run full validation quality evaluation before choosing a candidate. Then use
the frozen test split once for the selected candidate's final comparison.
Also check downstream detection: preserving PSNR alone is insufficient.
The bundled three repeated image samples measure throughput only, not mAP;
the four numerical fixtures are only an early rejection gate. The earlier
72-image CPU detection pilot does not measure quantized detection performance.

Adopt compression only when measured resource improvements meet the device
budget while quality remains acceptable. Reporting an unsuccessful pruning
ablation honestly still addresses the pruning research question. It does not
justify replacing a better model just to tick a deployment checklist.
