JETSON NANO / JETAUTOPRO DETECTOR DEMO
====================================

TensorRT 8.2.1.8, numpy 1.19.4, OpenCV 4.5.5, PyCUDA and ROS installed.
This standalone runner deliberately does not install the main Python package,
change system Python or require cv_bridge, whose local compiled extension
failed to load under Python 3.6.

1x3x640x640 input, 1x84x8400 output, 18.1549 queries/sec over a 3.08456-second
random-input run. This is user-supplied engine benchmark evidence, not live
camera FPS, a sustained benchmark, detection accuracy, or Restormer performance.
Actual layer precision has not been audited. Restormer is optional below.

Download scripts/deployment/nano_yolo_demo.py to ~/aegis-nano/nano_yolo_demo.py
from a pinned repository commit. No dependency installations are needed on the
reported Nano. Keep the existing robot services and system libraries intact.

From ~/aegis-nano, set:
  export AEGIS_KIT="$HOME/aegis-nano/aegis_edge_integrated_20261030"

Validate the already built engine; do not rebuild:
  /usr/bin/python3 nano_yolo_demo.py --engine engines/yolov8n_fp16_candidate.engine --fixtures "$AEGIS_KIT/artifacts/edge_v1/exports/yolov8n/fixtures.npz" --validate-only --output results/yolo_validation_01

Continue only if passed=true. A rejected engine is not approved just because
trtexec succeeded. Successful checks are cached next to the engine and reused
only when engine, fixture, runtime-script hashes and TensorRT version match.
Fixture hashes are pinned; validation records engine and runner hashes.

Saved camera image:
  /usr/bin/python3 nano_yolo_demo.py --engine engines/yolov8n_fp16_candidate.engine --fixtures "$AEGIS_KIT/artifacts/edge_v1/exports/yolov8n/fixtures.npz" --image results/astra_camera_test.png --output results/yolo_image_01

Outputs: validation.json, first.jpg, latest.jpg, detections.jsonl, summary.json.
Only person, bicycle, car, motorcycle, bus and truck are displayed. Zero road
objects indoors is possible and is not automatically a runtime failure.
Detection confidence is not accuracy. New runs require new output directories.

Live Astra RGB, on the Jetson (Ctrl+C stops cleanly):
  /usr/bin/python3 nano_yolo_demo.py --engine engines/yolov8n_fp16_candidate.engine --fixtures "$AEGIS_KIT/artifacts/edge_v1/exports/yolov8n/fixtures.npz" --topic /astra_cam/rgb/image_raw/compressed --max-frames 0 --serve 8080 --output results/yolo_live_01

ROS callback keeps only the latest message, so frames can be dropped during
processing rather than building an unbounded inference queue. CUDA calls stay
on the main thread. No new direct camera capture is opened. Camera input is
compressed; this is not a lossless restoration-quality evaluation protocol.

On the LAPTOP, open a separate terminal and substitute the SSH address:
  ssh -N -L 8080:127.0.0.1:8080 jetauto@JETSON_IP
Leave that command running, then open http://127.0.0.1:8080 in the laptop browser.
The preview shows latest processed images, refreshed approximately every 300ms.
Browser refresh rate is not inference FPS. Preview is bound to localhost only.
It stops when the runner stops. No camera footage is sent to a third-party host.

CPU tests cover Python 3.6 syntax, RGB/letterbox geometry, class-aware NMS,
reference rejection and localhost preview. Actual TensorRT/PyCUDA execution
and ROS integration require running the script on the user's Nano; they have
not been tested on developer hardware. If validation rejects, preserve its
JSON and the build log rather than weakening limits.

This script is a separate Nano adapter; it does not modify the frozen Orin
archive or add custom quantization. Hardware compatibility still requires the
user to execute the build and checks on the Nano.

RESTORMER + YOLO
---------------
Download nano_restormer.py beside the updated nano_yolo_demo.py from the SAME
repository commit. The helper uses system Pillow (python3-pil); install that
OS package only if 'from PIL import Image' fails. No training/PyTorch required.

Build and check trained Restormer (epoch 51) in one command:
  /usr/bin/python3 nano_restormer.py --onnx "$AEGIS_KIT/artifacts/edge_v1/exports/256x448/restormer/restoration.onnx" --fixtures "$AEGIS_KIT/artifacts/edge_v1/exports/256x448/restormer/fixtures.npz" --output engines/restormer_mixed.engine --workspace 256

This permits FP16 convolution tactics and constrains sensitive transformer
math to FP32. It is not INT8. Both the trained graph and four-weather fixtures
are hash-pinned. The candidate must meet original output agreement and clean
reference PSNR/SSIM limits. Only a passing candidate gets the final filename.
Build logs, parser or memory failures must not be interpreted as successful
deployment. Memory feasibility and actual throughput remain unmeasured until
the user runs the model. No automatic power-mode or system-service changes.

Add these options to the image or live command, using the validated FP32 YOLO
engine and a fresh output directory:
  --restorer engines/restormer_mixed.engine --restorer-fixtures "$AEGIS_KIT/artifacts/edge_v1/exports/256x448/restormer/fixtures.npz"

Preview: original on left, restored with road detections on right. Restoration
uses the same RGB [-1,1], aspect-preserving PIL bilinear resize and bottom/right
edge padding as the frozen pipeline. Output is unpadded, clipped, rounded and
resized back before detection. Two models share a primary CUDA context, with
explicit balanced context selection for each model call. This is not proof
of restoration improving detection; a labelled evaluation would establish that.
